# 判断子序列：双指针贪心解法分析

> 题目内容：给定两个字符串 `s` 和 `t`，判断 `s` 是否为 `t` 的子序列。子序列是从原字符串中删除若干字符（可以不删除）后、保持剩余字符相对顺序得到的新字符串。
>
> 题源：[LeetCode 392（中文）](https://leetcode.cn/problems/is-subsequence/description/) / [LeetCode 392（英文）](https://leetcode.com/problems/is-subsequence/)
>
> 实现：[src/string/is_subsequence.rs](https://github.com/delight-rs/rust-algorithm/blob/main/src/string/is_subsequence.rs)
>
> 一句话概括：用一个下标记录 `s` 的匹配进度，从左到右扫描 `t`，匹配成功就前进，时间 O(n)、额外空间 O(1)。

为书写方便，下文记 `m = len(s)`、`n = len(t)`。

## 1. 输入与输出

### 1.1 输入

| 项     | 内容                                                     |
| ------ | -------------------------------------------------------- |
| 参数   | `Solution::is_subsequence(s: String, t: String) -> bool` |
| 规模   | `0 <= m <= 100`，`0 <= n <= 10^4`                        |
| 取值   | `s`、`t` 仅包含小写英文字母；允许空串；字符可以重复      |
| 特殊值 | `m = 0`、`n = 0`、`s == t`、`m > n`                      |

### 1.2 输出

返回 `true` 当且仅当存在严格递增的下标序列：

```text
0 <= j0 < j1 < ... < j(m-1) < n，且 t[jk] == s[k]（k = 0..m-1）
```

当 `m = 0` 时，空下标序列满足条件，结果为 `true`。

### 1.3 示例

| `s`     | `t`        | 输出    | 说明                            |
| ------- | ---------- | ------- | ------------------------------- |
| `"abc"` | `"ahbgdc"` | `true`  | 匹配位置 0、2、5，可以跳过字符  |
| `"axc"` | `"ahbgdc"` | `false` | `'x'` 不在 `t` 中               |
| `"ace"` | `"abcde"`  | `true`  | 非连续，但顺序保持              |
| `"aec"` | `"abcde"`  | `false` | `'e'` 在 `'c'` 之后，顺序不满足 |

### 1.4 边界与约束

- 题面保证：字符集为小写英文字母；长度范围如 1.1 所示。
- 代码隐含假设：按 UTF-8 字节比较。题目字符均为单字节 ASCII，字节与字符一一对应，因此语义与字符级一致。
- 代码自带处理：`s` 为空时显式返回 `true`；`t` 为空时循环不执行，最后比较 `i == m`，只有 `m = 0` 时返回 `true`。
- 需要特别说明：`if s.is_empty()` 是快速路径而非必需分支。删除后，循环体一次也不执行，最终 `0 == 0` 仍返回 `true`。

## 2. 文件中的实现

文件有一个实现 `is_subsequence`，采用双指针贪心：一个指针记录 `s` 的进度，另一个指针由 `for` 循环隐式遍历 `t`。

### 2.1 双指针贪心

- 思路：`i` 表示 `s` 中下一个待匹配的位置。依次遍历 `t` 的每个字节 `b`，若 `s_bytes.get(i) == Some(b)`，说明当前 `t` 字符可以承接 `s[i]`，执行 `i += 1`；否则跳过该字符。扫描结束后判断 `i == m`。
- 时间/空间：O(n) / O(1)。
- 局限：每次查询都要扫描 `t`。当 `t` 固定且查询非常多时，应预处理 `t`（见第 6 节）。

步骤：

1. 若 `s` 为空，返回 `true`。
2. 令 `i = 0`，取 `s.as_bytes()`。
3. 遍历 `t.as_bytes()`，当 `s_bytes.get(i) == Some(b)` 时执行 `i += 1`。
4. 返回 `i == s_bytes.len()`。

`s_bytes.get(i)` 在下标越界时返回 `None`，与任何字节都不相等，因此当 `i == m` 后循环继续执行也不会 panic。若写成 `s_bytes[i]`，则必须在比较前额外判断 `i < m`，否则会触发索引越界 panic。

### 2.2 状态追踪

以 `s = "abc"`、`t = "ahbgdc"` 为例：

| 轮次 | `t` 当前字符 | 匹配前 `i` | `s` 待匹配字节 | 是否匹配 | 匹配后 `i` |
| ---- | ------------ | ---------- | -------------- | -------- | ---------- |
| 1    | `'a'`        | 0          | `b'a'`         | 是       | 1          |
| 2    | `'h'`        | 1          | `b'b'`         | 否       | 1          |
| 3    | `'b'`        | 1          | `b'b'`         | 是       | 2          |
| 4    | `'g'`        | 2          | `b'c'`         | 否       | 2          |
| 5    | `'d'`        | 2          | `b'c'`         | 否       | 2          |
| 6    | `'c'`        | 2          | `b'c'`         | 是       | 3          |

循环结束时 `i = 3 = m`，返回 `true`，对应匹配位置为下标 0、2、5。

对于 `s = "axc"`、`t = "ahbgdc"`，`'a'` 匹配后 `i = 1`；`t` 中不存在 `'x'`，`i` 保持为 1；循环结束 `1 != 3`，返回 `false`。

### 2.3 正确性说明

- 循环不变量：处理完 `t` 的前 `k` 个字节后，`i` 等于 `s` 的最长前缀长度，且该前缀是 `t[0..k]` 的子序列。
- 归纳：初始 `k = 0`、`i = 0`，空前缀满足条件。处理第 `k` 个字节时，若它与 `s[i]` 相等，则把已匹配前缀延长一位；否则保持不变。两种情况都保持不变量。
- 贪心选择的正确性（交换论证）：假设某个可行匹配把 `s[i]` 对应到 `t[q]`，而扫描中遇到的最早可匹配位置是 `p`，则 `p <= q`。把 `s[i]` 改配到 `p` 后，`s[i]` 之前的字符不受影响；对 `s[i+1..]` 来说，`p <= q` 保证原来可用的后续位置仍然可用。因此选择最早位置不会使可行解变差。
- 终止：扫描完 `t` 后，`i == m` 当且仅当整个 `s` 被匹配。空串由提前返回或 `0 == 0` 覆盖。
- 易错点：
    - 若把「已完成」的判断放在循环体开头并直接 `return true`，当最后一个匹配字符恰好是 `t` 的最后一个字符时，循环结束后不会再执行该判断，函数会错误返回 `false`。判断必须在循环结束后也能生效。
    - 直接索引 `s_bytes[i]` 在 `i == m` 时越界；`get` 用 `Option` 表达了「没有下一个待匹配字符」。
    - 按字节比较依赖题面的 ASCII 字符集；若扩展到多字节字符，需要改用字符级比较。

## 3. 为什么能想到这个方案

### 3.1 最直白的解法

按定义枚举 `t` 的所有子序列再与 `s` 比较：`t` 有 `2^n` 个子序列，完全不可行。

另一个常见的第一反应是最长公共子序列：用 O(m·n) 的动态规划求 `LCS(s, t)`，若长度等于 `m` 就返回 `true`。这个做法正确，但对「只需判断、不需要求最优匹配」的问题来说代价过高。

### 3.2 优化尝试及失败原因

- **只比较字符频次**：统计 `s` 与 `t` 中每个字符的出现次数，若 `s` 的频次不超过 `t` 就返回 `true`。反例：`s = "ba"`、`t = "ab"`，频次满足但顺序不满足。频次丢失了位置信息。
- **对每个字符都从 `t` 的起点查找**：每次查找独立进行，不知道上一次匹配到哪里，可能把已经用过的位置再次选中，也可能漏掉正确的相对顺序。
- **只维护布尔状态**：无法记录 `s` 的匹配进度，遇到重复字符时无法判断应该匹配哪一个。

失败的本质原因：子序列同时要求「保持顺序」和「每个位置最多使用一次」，因此必须维护一个单调前进的位置信息；频次和布尔值都不足以表达这个信息。

### 3.3 换视角拆解

把问题看成「为 `s` 的每个字符按顺序在 `t` 中找位置」。因为 `t` 中允许跳过任意字符，匹配 `s[i]` 时选择越早的位置，留给后续字符的空间越大。于是有：

```text
s 的匹配进度 i 只增不减，t 只需从左到右扫描一次
```

`t` 的下标随循环前进，`s` 的下标只在匹配时前进，两者都不回退，所以总时间是 O(n)。这是双指针贪心的一种形式：一个显式的进度指针 `i`，另一个是 `for` 循环隐含的遍历位置。

### 3.4 空间优化

只需一个整数 `i`。`as_bytes()` 返回对原字符串的借用，不复制内容，所以额外空间是 O(1)。对单次查询来说，建立索引的成本与直接扫描同为 O(n) 量级（下一出现位置表还多出 26 倍常数），却要额外占用空间，因此没有必要。

### 3.5 可迁移的模板

> 当问题要求「按顺序匹配一个模式串，且源串的每个位置最多使用一次」时，可以用一个下标记录模式串的匹配进度，对源串做一次单向扫描，每次匹配选择最早可用的位置。时间复杂度 O(源串长度)，额外空间 O(1)。

| 同类问题                             | 模式串     | 进度指针                             | 与本题的差异                |
| ------------------------------------ | ---------- | ------------------------------------ | --------------------------- |
| 392 判断子序列                       | 单个 `s`   | `s` 中下一个待匹配位置               | 一次扫描即可                |
| 792 匹配子序列的单词数               | 多个单词   | 每个单词一个进度指针，按当前字符分桶 | 扫描 `t` 时批量推进所有单词 |
| 524 通过删除字母匹配到字典里最长单词 | 多个候选词 | 每个候选词一个进度指针               | 需要选出最长且字典序最小者  |
| 合并两个有序数组                     | 两个数组   | 各数组的读取位置                     | 没有跳过语义，必须逐个取用  |

## 4. 复杂度对比

| 实现                 | 时间                         | 额外空间     | 前提/限制                        |
| -------------------- | ---------------------------- | ------------ | -------------------------------- |
| 双指针贪心（本文件） | O(n)                         | O(1)         | 单次查询；字符集需与字节一一对应 |
| 最长公共子序列 DP    | O(m·n)                       | O(min(m, n)) | 正确但过度设计                   |
| 枚举全部子序列       | O(2^n·m)                     | O(m)         | 只适合极小规模，不可用于题面范围 |
| 下一出现位置表       | 预处理 O(26n)；查询 O(m)     | O(26n)       | `t` 固定、查询量大的场景         |
| 位置表 + 二分查找    | 预处理 O(n)；查询 O(m·log n) | O(n)         | 查询量大且内存受限的场景         |

补充：

- 时间按字符比较次数计；`as_bytes()` 的遍历每字节 O(1)。
- 当前实现没有提前结束循环，即使 `s` 已全部匹配，仍会遍历 `t` 的剩余字节。加入 `if i == m { break; }` 可以缩短最好情况的耗时，但最坏情况仍是 O(n)。
- 额外空间不包含输入字符串与返回值。
- 算法只读，多个查询之间没有共享的可变状态，适合并行。
- 若 `t` 固定且查询极多，预处理方案把单次查询从 O(n) 降到 O(m) 或 O(m·log n)，代价是一次性预处理与额外空间。

## 5. 实际应用场景

| 场景               | 匹配内容                                                     | 为什么适合单次扫描                           |
| ------------------ | ------------------------------------------------------------ | -------------------------------------------- |
| 用户行为序列校验   | 「登录 → 浏览 → 下单」等事件类型是否按顺序出现在会话日志中   | 事件流按时间排列，只要求相对顺序，不要求连续 |
| 日志与规则过滤     | 关键字序列是否按顺序出现                                     | 无关日志可以跳过，规则通常只约束顺序         |
| 模糊匹配与推荐     | 输入缩写是否按顺序出现在候选词中，如 `algo` 匹配 `algorithm` | 输入短、候选多，单次线性扫描成本低           |
| 生物信息学序列查询 | 模式序列是否按顺序出现在 DNA 或蛋白质序列中                  | 子序列不要求连续，允许中间存在其他片段       |
| 操作审计           | 关键操作是否保留了规定的先后关系                             | 只校验顺序，不要求操作相邻                   |

工程注意：

- **字符与字节**：当前实现按 UTF-8 字节比较。ASCII 范围内字节与字符一一对应；处理中文等多字节字符时，字节级匹配可能与字符级语义不同。工程中应明确匹配层级，必要时使用 `chars()` 或先做 Unicode 规范化。
- **大小写与规范化**：实际匹配通常需要统一大小写，或对 Unicode 做 NFC/NFD 规范化，否则结果可能不符合用户预期。
- **海量查询**：`t` 固定而查询量大时，应预处理 `t`。下一出现位置表把查询降到 O(m)，位置表 + 二分把查询降到 O(m·log n)；预处理结果只读，可多线程共享。
- **流式输入**：若 `t` 持续到达，双指针可以在线推进；预处理方案要求 `t` 已完整可知。
- **内存**：下一出现位置表需要 `26 × (n + 1)` 个 `u32`，`n = 10^4` 时约 1 MB；内存受限时优先考虑位置表 + 二分。

## 6. 延伸与变体

| 变体                    | 做法                                                                                                          | 关键点                                             |
| ----------------------- | ------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| 海量 `s` 查询固定的 `t` | 预处理下一出现位置表：`next[i][c]` 表示从下标 `i` 起字符 `c` 的最早位置，不存在记为 `n`；查询时 `pos = p + 1` | 预处理 O(26n)，单次查询 O(m)，是查询侧的最优复杂度 |
| 查询量大且内存受限      | 记录每个字符在 `t` 中的有序下标，查询时二分查找第一个大于当前位置的下标                                       | 预处理 O(n)，单次查询 O(m·log n)                   |
| 判断连续子串            | KMP、`str::contains` 或滑动窗口                                                                               | 连续要求更强，不允许跳过字符                       |
| 统计不同子序列个数      | 动态规划，按字符去重                                                                                          | 计数问题，需要处理重复方案                         |
| 最长公共子序列          | O(m·n) 动态规划                                                                                               | 子序列判定是特例，用 DP 属于过度设计               |
| 多个模式串同时匹配      | 792 的桶分组做法                                                                                              | 避免每个模式串都完整扫描 `t`                       |
| `s` 或 `t` 动态更新     | 双指针重新扫描，或维护索引结构                                                                                | 一次性预处理的前提被破坏                           |

下一出现位置表的查询过程可以概括为：

```text
pos = 0
for c in s:
    p = next[pos][c]
    if p == n:
        return false
    pos = p + 1
return true
```

`pos` 表示下一次允许搜索的起点，`p + 1` 保证同一个 `t` 位置不会被使用两次。

## 7. 实现

```rust
struct Solution;

impl Solution {
    pub fn is_subsequence(s: String, t: String) -> bool {
        if s.is_empty() {
            return true;
        }

        let mut i = 0;
        let s_bytes = s.as_bytes();

        for b in t.as_bytes() {
            if s_bytes.get(i) == Some(b) {
                i += 1;
            }
        }

        i == s_bytes.len()
    }
}
```

- 题面最大规模：`m = 100`、`n = 10^4`。

可补强：

- 单字符不在 `t` 中（如 `"z"` / `"abc"`），单独覆盖「字符缺失」分支；
- `i` 到达 `m` 后 `t` 仍有大量剩余字符（如 `"a"` / `"a" + "b".repeat(9999)`），持续走 `get` 返回 `None` 的路径；
- 同一字符组成且 `n > m`（如 `"aa"` / `"aaa"`），覆盖重复字符的成功匹配；
- 随机对拍：小规模随机输入与暴力枚举或 O(m·n) 朴素实现比较；
- 约束外行为固定：大写字母、多字节字符的当前字节语义，避免后续修改无意改变行为。
