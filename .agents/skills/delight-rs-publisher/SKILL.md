# delight-rs 多平台发布文案

## 何时使用

- 用户提供技术文章正文、算法笔记或源码，要求生成发布标题、平台摘要、推荐标签或文末引流话术。
- 用户要求把同一篇内容改造成适合 CSDN、掘金、知乎、博客园、阿里云开发者社区的发布版本。
- 用户要求在发布场景下按平台定制摘要（各平台摘要风格不同，见「五平台摘要规范」）。

不适用：要求分析算法本身（用 `algorithm-analysis`）；只需要一份与平台无关的通用摘要、不涉及发布（用 `algorithm-summary`）；整理标准库 API 笔记（用 `doc-write`）。

## 品牌锚点（固定不变）

| 项         | 值                                                                            |
| ---------- | ----------------------------------------------------------------------------- |
| 品牌标识   | `delight-rs`                                                                  |
| 核心专栏名 | `Rust 算法硬核拆解`；非算法类内容可微调为 `Rust 工程实战`                     |
| 引流目标   | GitHub 仓库 `https://github.com/delight-rs/rust-algorithm`（Star 与技术交流） |

## 输入与产物

| 项       | 说明                                                                                     |
| -------- | ---------------------------------------------------------------------------------------- |
| 输入     | 文章正文/笔记/源码；可选：指定平台（默认五平台全出）                                     |
| 产物     | 核心卖点提炼 + 五平台标题（每平台 2 个）+ 五平台定制摘要 + 五平台文末 CTA + 5 个通用标签 |
| 输出方式 | 直接输出，默认不新建文件                                                                 |

## 工作流程

1. **内容解构**：提取四个核心要素。
2. **五平台标题**：按各平台公式生成【主推稳健款】+【进阶高点击款】两个标题。
3. **五平台摘要**：按「五平台摘要规范」为每个平台写一份定制摘要。
4. **五平台 CTA**：按各平台模板生成文末引流块，替换主题变量。
5. **通用标签**：生成 5 个高频技术标签。
6. **校验**：按文末清单自检后输出。

### 1. 内容解构四要素

| 要素            | 说明                              | 示例                                               |
| --------------- | --------------------------------- | -------------------------------------------------- |
| 技术栈/语言     | 默认 Rust，兼顾通用数据结构与算法 | Rust、`Vec`、迭代器                                |
| 具体场景/题号   | 题源、编号、完整题名              | LeetCode 443 字符串压缩                            |
| 核心解法/技术词 | 解法名与关键术语                  | 双指针、循环不变量、零拷贝、内存安全               |
| 差异化亮点      | 本文独有的价值点                  | 完整单元测试、复杂度严格证明、状态追踪表、避坑指南 |

- 题号、题名、复杂度等事实必须来自原文；原文没有时不编造，在卖点中标注「原文未注明」。
- 亮点提炼 1–3 条，优先选读者能直接感知的（测试、证明、图表、避坑）。

### 2. 五平台标题规范

每个平台输出两个标题，二者必须**实质差异化**：

- 【主推稳健款】：严格套用平台公式，关键词完整、信息密度高，适合长期搜索流量。
- 【进阶高点击款】：允许打破公式，用认知差、痛点提问或反常识结论制造点击，但不得偏离文章事实。

#### CSDN（极致 SEO + 关键词全覆盖）

- 标题公式：`【Rust算法硬核拆解】题号 + 完整题名（核心算法 / 关键技术词 / 附加亮点）`
- 建议长度 ≤ 40 字；必须包含完整英文专有名词（LeetCode、Rust）与中文译名，禁止谜语人式标题。
- 进阶款：把括号内亮点替换为可下载价值点，如「附完整单测」「复杂度严格证明」。

#### 掘金（技术干货 + 社区调性 + 高收藏率）

- 标题公式：`Rust 算法硬核拆解｜核心主题：具体技术方案与深度亮点剖析`
- 建议长度 ≤ 30 字；分隔符用 `｜` 或 `：`，避免 `【】` 堆砌；突出「深度剖析」「实战」「状态追踪」等收藏驱动词。
- 进阶款：可用「N 个细节」式结构制造收藏动机，但 N 必须真实可数。

#### 知乎（深度思辨 + 痛点提问 + 好奇心驱动）

- 标题公式：`用 Rust 写 [核心主题]：如何严格解决/证明 [核心技术痛点]？` 或 `[核心主题]：为什么很多常规方案其实存在 [反常识缺陷]？`
- 建议长度 ≤ 30 字；不带生硬专栏前缀；必须是一个真实存在的问题，且文中给出答案。
- 进阶款：反常识切入，例如「为什么这题 90% 的题解都忽略了 X」，X 必须是文中确实指出的缺陷。

#### 博客园（极客纯粹 + 笔记沉淀 + 简洁清晰）

- 标题公式：`[Rust 算法笔记] 核心主题 - 关键技术点与实现细节总结`
- 建议长度 ≤ 30 字；去掉一切营销感与夸张词汇，直击技术本质。
- 进阶款：突出具体技术细节词（如「循环不变量」「零拷贝」），而非平台化表述。

#### 阿里云开发者社区（企业级实战 + 架构演进 + 最佳实践）

- 标题公式：`Rust 工程实践：基于 [核心技术] 的 [主题] 性能优化与原理解析`
- 建议长度 ≤ 35 字；把局部算法上升到「内存分配优化」「系统稳定性」「复杂度工程权衡」的高度。
- 进阶款：加「生产环境」「最佳实践」等词，指向读者可落地的工程收益。

### 3. 五平台摘要规范

摘要承接 `algorithm-summary` 的提炼规则，并按平台风格定制。先遵守通用规则，再套用各平台公式。

#### 通用提炼规则（所有平台遵守）

- **保留**：主题/题号、核心解法、时间复杂度与空间复杂度、关键亮点；有多解时只写最优解，可用一个短语点明另一实现。
- **删除**：示例数据、状态追踪表、循环不变量证明、测试覆盖评价、应用场景清单。
- **字数口径**：汉字、标点、数字、英文字母各计 1，空格与换行不计；「≤ N 字」按此口径校验。
- **事实约束**：题号、题名、复杂度、亮点必须来自原文，原文没有的不补充、不编造。
- **语言**：简体中文，专有名词保留英文（LeetCode、gcd、`O(n)`）；允许行内代码标记复杂度与标识符。
- **禁用**：感叹号与营销词（深入浅出、全面、终极）；「本文」只允许作为平台公式的开头出现，其后必须紧跟具体内容（技术词、复杂度），禁止「本文详细介绍了……的深入分析」这类空话。
- **与标题联动**：摘要中的题号、复杂度必须与标题一致；摘要不得与标题逐字重复。

#### CSDN（SEO 关键词型）

- 目标：搜索摘要位也能吃满关键词。
- 公式：`【题号 + 完整题名】用 [核心算法] 实现：时间 O(x)、空间 O(y)。附 [亮点]。`
- 长度 ≤ 100 字；覆盖题号题名、核心解法、复杂度、1 个亮点。
- 禁用反问与悬念句式。

#### 掘金（深度收藏型）

- 目标：展示工程细节与推导深度，刺激收藏。
- 公式：`拆解 [主题]：核心思路 [技术词]，并附 [亮点1]、[亮点2]，重点讲清「为什么正确」。`
- 长度 60–90 字；强调证明、状态追踪、工程级细节。

#### 知乎（认知差提问型）

- 目标：抛痛点、制造好奇心，引导读全文。
- 公式：`常规做法存在 [缺陷]；本文用 [技术词] 给出严格解（O(x)/O(y)），关键在于 [转折点]。`
- 长度 40–70 字；允许一个问句制造悬念，但正文必须给出答案。

#### 博客园（极客克制型）

- 目标：作为笔记开头，纯技术、无营销。
- 公式：`[主题]：以 [核心算法] 求解，时间 O(x)、空间 O(y)，要点：[关键点]。`
- 长度 40–80 字；不加任何平台化修饰。

#### 阿里云开发者社区（工程价值型）

- 目标：突出性能收益与生产可复用性。
- 公式：`基于 [核心技术] 优化 [主题]，复杂度降至 O(x)/O(y)，减少 [内存分配/拷贝开销]，可直接复用于 [场景]。`
- 长度 60–100 字；「复用场景」必须来自原文的应用场景部分，没有则不写。

### 5. 通用标签（5 个）

按以下顺序输出 5 个：

1. 语言/生态标签：`Rust`
2. 题源标签：`LeetCode`（非算法类内容改为内容主题词）
3. 核心解法/技术词：如 `双指针`、`动态规划`（取自解构要素）
4. 差异化亮点词：如 `单元测试`、`算法优化`（没有亮点则用场景词）
5. 品牌标签：`delight-rs`

要求：每个标签都是平台真实存在或高频检索的词；不用与文章无关的热词蹭流量；不超过 5 个。

## 写作规则

- 简体中文，专有名词保留英文（Rust、LeetCode、Star）。
- 标题不夸大：禁用「最强」「史上最全」「吊打」「秒杀」等词；禁止标题与正文事实不符。
- CTA 不承诺虚假权益（如「加群送资料」），不写低俗引流话术。
- 标题与 CTA 中出现的题号、复杂度、亮点，必须与输入内容一致。
- 平台顺序固定：CSDN、掘金、知乎、博客园、阿里云。

## 参考模板

完整的产出结构见 `templates/publish-copy-template.md`，其中以《LeetCode 283 移动零》为例填好了卖点、五平台标题/摘要/CTA 与标签，并标注了实测字数。

使用要点：

- 先完成「内容解构四要素」，再对照模板逐平台替换题号、题名、技术词、亮点、复杂度与场景；
- 标题、摘要、CTA 三处的题号与复杂度必须保持一致，替换后按各平台长度上限重新数字数；
- CTA 中的 `{技术词}`、`{技术痛点}`、`{场景}` 变量需替换为当篇内容，并保留仓库地址与 Star 邀请；模板中 `<https://...>` 的尖括号是 Markdown 源码写法，发布输出时去掉尖括号；
- 模板只是结构提示，不必逐字照抄；不得为了套模板而编造原文没有的题号或亮点。

## 校验

- [ ] 五个平台各 2 个标题，稳健款符合平台公式，进阶款与稳健款实质差异化。
- [ ] 五个平台各 1 份摘要，符合对应平台的公式与长度区间，且保留复杂度信息。
- [ ] 摘要与标题、CTA 中的题号、复杂度一致，无编造、无夸大词。
- [ ] 每个 CTA 包含真实仓库地址 `https://github.com/delight-rs/rust-algorithm` 与 Star 邀请。
- [ ] 标签恰为 5 个，且与文章内容相关。
- [ ] 题号、题名、技术词与输入内容一致，未编造。
- [ ] 标题与 CTA 无夸大词、无营销违规词。
- [ ] 输出按「卖点 → 标题、摘要与 CTA → 标签」结构排列，可直接复制，结构对齐 `templates/publish-copy-template.md`。

## 汇报格式

按以下结构直接输出，不做长篇解释：

1. **核心卖点提炼**：2–3 行概括本文技术亮点。
2. **五平台标题、摘要与 CTA**：按 CSDN、掘金、知乎、博客园、阿里云顺序，每平台输出【主推标题】【进阶标题】【平台摘要】【文末引流块】。
3. **通用标签**：一行 5 个标签，用空格分隔。

若用户只想调整某平台标题或 CTA 语气，在文末列出可调整项供其选择。
