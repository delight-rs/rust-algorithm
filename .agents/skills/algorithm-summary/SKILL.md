# 算法笔记摘要

## 何时使用

- 用户给出 `.md` 分析笔记、题解或源码，要求「总结」「概括」「提炼」「压缩成 N 字以内」。
- 用户要求给某篇算法文档补一段开头的摘要。

不适用：

- 要求完整分析算法（使用 `algorithm-analysis`）。
- 要求整理标准库 API 笔记（使用 `doc-write`）。
- 用户实际要的是改代码、修 bug 或优化性能。

## 输入与产物

| 项 | 说明 |
| -- | ---- |
| 输入 | 目标文件路径，或对话中已提供的全文；用户指定的字数上限 |
| 产物 | 一段中文摘要，默认直接输出，不新建文件 |
| 字数口径 | 汉字、标点、数字、英文字母各计 1；空格与换行不计 |
| 默认上限 | 100 字；无明确要求时目标 80–95 字，留出余量 |

写入文件仅在用户明确要求时执行，默认不改动原文档。

## 提炼顺序

按信息价值从高到低取舍，命中前四项即可成稿：

1. **是什么**：算法或题目的名称、编号，以及一句话用途。
2. **核心解法**：最关键的那一个技巧，用动词短语表达，例如「正序写前缀积、逆序乘后缀积」。
3. **复杂度**：时间与额外空间，使用 `O(n)`、`O(1)` 形式。
4. **关键约束或亮点**：不使用除法、天然处理 0、无需逆元、可流式处理等。
5. **次要信息**：易错点、变体、应用场景。只在字数允许时出现，且压缩成短语。

必须删除：示例数据、状态追踪表、循环不变量证明、测试覆盖评价、两种实现的对拍细节、应用场景清单。

## 写作规则

- 单段成文，不用标题、列表或代码块。
- 允许行内代码标记复杂度与标识符，如 `O(n)`。
- 使用简体中文，专有名词保留英文（LeetCode、gcd、log）。
- 只写原文有依据的内容；数字、复杂度、约束必须与原文一致，原文没写的不补充。
- 不写「本文」「这篇笔记详细介绍了」之类的空话，直接给结论。
- 不用感叹号和营销词（深入浅出、全面、终极）。
- 有多解时只保留最优解的必要信息，可用一个短语点明另一实现，例如「另附 O(n²) 暴力对拍版」。

## 示例

> LeetCode 238 笔记：正序写前缀积、逆序乘后缀积，两遍扫描实现 O(n) 时间、O(1) 额外空间。核心是把「排除自身」拆成左段 × 右段，不依赖除法即可天然处理 0；另附正确性证明、变体与工程应用场景。

## 写入笔记（可选）

仅当用户说「写进文档」「加到开头」时：

- 在主标题与正文之间插入一行引用块：`> **摘要**：……`。
- 不改动文档其他内容。
- 写完运行 `npx --yes markdownlint-cli <文件路径>` 并如实汇报结果。

## 校验

1. 确认摘要包含主题、核心解法、复杂度三项。
2. 统计字数：汉字、标点、数字、字母各计 1，空格与换行不计；超限时先删次要信息。
3. 回查原文，确认没有新增原文未提的结论、复杂度或场景。
4. 用户指定「N 字内」时，确保不超过 N，并尽量达到 N 的 80% 以上。

## 汇报格式

直接给出摘要，可标注实际字数，例如「（约 90 字）」。不做长篇解释，用户要求展开时再说明取舍过程。
